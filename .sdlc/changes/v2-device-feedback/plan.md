## Problem

五期 V2（`ui-v2-redesign`）的 Test 只覆盖到桌面 Chromium 模拟视口（430×932），
`interaction-motion-h5/test.md` 的 Untested 第一条已点名「**真触摸串（pointerdown → move → up 的
scroll-snap 拖拽）未覆盖**」，`ui-v2-redesign/maintain.md` 也把「真机走查」留成未关闭的 Follow-up。
用户真机上手后，这些没测到的地方立刻暴露：

1. **第一步页（编辑既有 DO）点左上「返回」无法返回**，页面被弹回第一步页，观感是「返回键一直卡」。
2. **今天 ↔ 痕迹的左右滑动失效**：手指拖不动（指示胶囊与程序化滚动都正常）。
3. **首页「一个模糊的念头」卡里的三个推荐示例**（跑步 10 分钟 / 做一顿饭 / 拍一张照片）
   把「模糊的念头」收窄成三个固定答案，与「写一句就行」相抵。
4. **痕迹导出卡片的样式 / 模板需要重新设计**（用户明确：最后做，届时再讨论）。

1 与 2 都不是「新功能没做」，而是**五期已判过 `pass` 的行为在真实触摸链路下不成立**：
四期的横滑结论建立在 `scrollLeft = 430` 的程序化验证上，从没有真手指拖过。

## Desired outcome

- 第一步页（无论从对话页还是从「正在进行」卡进入）点返回都能**一次到位回到今天页**，不重发请求、不弹回。
- 今天 ↔ 痕迹可以用手指左右滑动切换，越过中点指示胶囊跟手，松手落到整数页。
- 念头卡只留输入框与「帮我找到第一步」，不给推荐答案。
- 卡片改版不混进本轮：留下讨论维度，等人工拍板后另开一轮。

## Scope

### In scope

1. **#42 第一步页返回**：ActionPage 的左上返回由 `setScreen('input')` 改为 `useExpandTransition().leave()`
   （播收回动画后回首页），并保证编辑态的 `activeDOId` / `idea` 被清干净。
2. **#43 分页手势**：App 里 `tab → 分页位置` 的 effect 增加**来源区分**——手势（拖拽/惯性）驱动的
   tab 变化不再调用 `scrollTo`，避免程序化滚动打断原生触摸滚动。
3. **#44 念头卡去 chip**：删 `EXAMPLE_IDEAS`、`.idea-chips` 区块与对应样式，`DESIGN.md §3` 同步。
4. 文档同步：`DESIGN.md`（念头卡描述、行动页返回语义）、`docs/TODO.md`、`.sdlc/DAILY.md`。

### Out of scope

- **#45 卡片改版**：本轮不动 `card-render.ts` / `ShareCard.tsx`，只登记讨论维度（见 Open decisions）。
- 记录页（RecordPage）的返回、全屏查看器的手势：本轮不动（若是同类缺陷，作为 #42/#43 的延伸另开条目）。
- 真机自动化测试基建（无头浏览器装不上：`agent-browser` 的可执行文件被本机应用控制策略拦截，
  `playwright-cli` 未安装）——本轮接受「推理 + 桌面可验证部分 + 用户真机确认」这一证据强度上限。

## Constraints

- 不改存储 schema、不改 `docs/DO-PROMPT.md` 的 AI 契约、不删既有功能。
- 页面切换仍禁用 `AnimatePresence`；容器变换与形状守恒（DESIGN §5.1）继续生效——
  返回必须走 `leave()` 播收回动画，不能直接切状态硬跳。
- 手机优先；桌面 430×900 手机框行为不变。
- 门禁：本 change 的 plan / design / build / test 四件套必须齐全且非空。

## Success criteria

- [ ] 编辑态（正在进行卡 → 第一步页）点返回：落到今天页，`screen === 'home'`，且**不产生新的 AI 请求**。
- [ ] 从对话页进入的第一步页点返回：同样落到今天页，念头不残留、`activeDOId === null`。
- [ ] 分页 effect 在「手势驱动 tab 变化」时不再设置 `guardedUntil`、不再调用 `scrollTo`；
      点 Tab 的程序化滚动行为不变。
- [ ] 今天页黑卡内不再出现示例 chip；输入框、蜜桃胶囊、`growTextarea` 行为不变。
- [ ] `npm run typecheck`、`npm run build` 通过。
- [ ] 桌面模拟可验证的部分留下证据（DOM/样式断言与截图），真触摸部分明确标注待用户真机确认。

## Open decisions

- [x] **#42 返回的落点（已定：回首页）**：第一步页的返回不再回对话页。理由：对话页是一次性动作
  （进页即自动发出首页那条念头并产出行动，见 DESIGN §2.2 第 2 条），回去只会**重跑一遍**，
  而「改念头」在首页黑卡里更直接。代价：失去「回上一步改措辞」的路径（本来也不成立——对话页
  不可编辑已发出的念头）。
- [x] **#43 手势与程序化滚动的边界（已定：谁发起谁负责）**：状态可以跟手（越过中点立刻翻），
  但**位置只由手势自己推进**；点 Tab 时反过来，状态先动、位置由程序化滚动跟上。
- [ ] **#45 卡片改版（待人工讨论后另开）** —— 需要拍板的维度：
  1. **画幅**：现在的卡片是「340px 宽 × 2x」的竖版自适应高度；是否改成固定比例（3:4 / 9:16）？
  2. **封面**：`#16` 已定「原比例不裁切」，而 V2 稿是满幅海报式裁切——这条要不要翻案？
  3. **模板数量**：仍 1 套，还是按记录形态（有图 / 纯文 / 多图）分 2–3 套？
  4. **信息层级**：「第 N 次尝试」徽章、时长、关联念头、署名，哪些留、哪些删？
  5. **导出与分享**：是否要出方形（朋友圈）/ 竖版（小红书）两种尺寸？
  6. 讨论结论落 `docs/CONTEXT.md` + `DESIGN.md §4`，再开 change 动手。
