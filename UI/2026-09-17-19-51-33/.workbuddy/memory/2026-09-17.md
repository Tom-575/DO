## DO · 移动端 App UI 设计稿（Ardot）

- 需求：按用户提供的 RouteMind 截图风格，为产品「DO」（把模糊念头变成真实尝试）重新设计一套高质量移动端 UI。
- 交付：Ardot 文件 `DO · 移动端 App UI`（fileId 726838202659969，https://ardot.tencent.com/file/726838202659969），6 屏核心闭环 + 2x PNG 6 张与整套 PDF（导出至 `DO-UI/`）。
- 屏幕：01 出发（Onboarding 满幅摄影）/ 02 今天（念头输入 + 进行中 + 最近痕迹）/ 03 第一步（最小行动 10 MIN）/ 04 记录（含「中途停下」「不适合我」等中性结果）/ 05 痕迹（统计 + 筛选 + 时间线）/ 06 分享卡。
- 从参考图提炼的视觉系统（可复用）：
  - 尺寸：Screen 393×852，外套黑色 Device（padding 10 / radius 56 / 白边），行间距 90。
  - 排版：Bebas Neue 做超窄体大字（正文标题、巨型数字如 10 / MIN / 12），Noto Sans SC 承担中文正文（Bold 30 做主标题、Regular 11–14 做辅助）。小写字母间距 +1~2 的 Bebas 做 kicker。
  - 色板：暖白底 #F7F5F2、墨 #0F0F0F、深面 #101010、蜜桃强调 #F2C9B4、陶土点缀 #C97B58、次级文字 #9A948C、发丝线 #ECE8E2。
  - 结构件：胶囊贯穿（按钮 r28 / chip r15-16 / 标签 r14 / 卡片 r18-28）；底部胶囊浮动导航（容器 393×95、pill 62h r36、内 padding 4、激活项白色实心 pill r26 + 10px 中文标签）；满幅图配上下双向黑色渐变遮罩；状态栏 62px。
- 踩坑记录：
  - `M(node, parent, index)` 的 index 是**子节点数组的 0 基索引**。首屏的 Status Bar 因先插入而位于图层最底，被后插入的满幅主图完全遮住（白字压亮图＝不可见）。解法：按「底→顶」顺序用 M 重排（photo → scrim → overlay → statusBar → logo → content → home indicator）。
  - 亮色满幅摄影必须有顶部 scrim（黑 a0.62 → 0.16 → 0），否则白色状态栏不可读。
  - `capture_layout` 的 parentId 不能传页面节点（报 "Root node must be a container, not a page"），要传具体 Frame。
  - 本机 Git Bash 环境 `mkdir`/`dirname`/`curl` 缺失（PATH 异常），文件下载与上传统一走 PowerShell 的 `Invoke-WebRequest`。
  - PowerShell 工具会拦截含 `%` 的字符串（误判为 cmd 变量语法），URL 里的百分号编码要用 `[System.Uri]::EscapeDataString($字面量)` 拼出来；`Write-Output` 不回显，改用 Glob/Read 验证产物。
  - `register_assets` 返回的预签名地址有效期约 15 分钟，批量上传时要检查每一张是否真的 PUT 成功（曾出现单张 403 → upload_images 报 "failed to download image: status=403"）。
