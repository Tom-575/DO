# DO 重启交接说明

> **状态：已归档（2026-09-13）。** 本文件是 9/12 视觉重启时的交接快照。其中的方向性决策已被 `docs/design/DESIGN_GRILL.md` 的确认记录取代（当前原型按 GRILL 走 iOS 质感 + 底部 Tab 方案）。保留仅供追溯当时的要求与失败教训，不要再按本文档执行视觉工作。

## 一句话定位

DO：把模糊念头变成一个可以立刻开始的最小行动，做过之后留下真实记录。

## 核心价值

用户不是缺少执行力，而是缺少清晰、足够小的第一步。

DO 不要求用户完成伟大目标，也不以成功作为唯一结果。它鼓励用户先开始，哪怕只做一点，哪怕最后没有完成，这次尝试也值得被留下。

## 用户与使用场景

- 用户本人就是 MVP 的直接使用者。
- 用户经常突然产生模糊念头，例如想运动、学做饭、拍照、旅行，或刷到一个视频后想试试。
- 用户知道自己想做什么，但经常停留在想法阶段，或者因为目标太大、太泛而迟迟不开始。
- 用户也希望记录真实生活，并将记录整理成高质量、可直接分享的内容。

## 已确认的产品原则

- 开始优先：先让用户做第一步。
- 一步原则：只给当前最小可执行动作。
- 真实优先：保留用户原话，AI 只整理，不虚构经历。
- 低压力：不制造打卡焦虑、连续 streak 或成功羞耻。
- 长期目标和一次性愿望都支持，但都要被拆成当前的一小步。
- “已记录”表示记录生命周期，不等于“已完成”。
- 记录可以不关联 DO，用户可以直接记录生活。
- DO 是写下念头的草稿。
- 记录是把发生过的事情留下来，类似翻开相册，但不是做实体相册拟物 UI。

## 首页必须解决的事

首页不是普通社交 App、Todo 工具、Dashboard 或卡片列表。

首页应该是一个沉浸式、单页、完整构图的视觉空间：

- 背景使用真实照片，照片本身承担氛围。
- 整体偏暗系，但不要堆渐变、光环、噪点或假光影。
- 背景可以是自然风景或日常生活照片，不能是明显摆拍的廉价室内素材。
- 不使用传统底部导航栏。
- 不使用卡片墙、三列模块、玻璃面板堆叠。
- 页面要有主次、层次、留白和明确的视觉焦点。
- 用户打开后应该先感到“想停留”，再理解“可以做什么”。

用户曾描述的氛围参考：

> 阳光穿过窗户，照在靠窗的书桌上。桌面上有一本相册，光影错落，治愈、舒适。

这段话表达的是氛围和摄影感，不是要求做桌面拟物 UI。

## DO 交互要求

这是目前最重要的交互，不能再做成普通按钮。

默认状态：

- 画面中有一个克制、好看的 DO 核心入口。
- DO 应该像画面中的一个物件或标记，而不是大号 CTA 按钮。
- 外观要高级、自然、可触碰，不能像廉价圆环、发光球或悬浮按钮。

点击状态：

```text
DO 小型状态
→ 同一个物件自然横向展开
→ 内部出现输入光标
→ 变成一条可输入的草稿入口
→ 输入完成后继续进入最小行动
```

关键要求：

- 输入框必须和 DO 是同一个共享容器。
- 不能点击 DO 后在页面另一处突然出现独立表单。
- 不能用硬编码坐标让两个独立组件假装有关联。
- 应使用 Motion 的 layout / layoutId 或同等共享元素方案。
- 动效表达“同一物件展开”，不是“页面切换”。
- 展开过程中应有明确的宽度、边界、光标和焦点变化。
- 要有 hover、active、focus 和 reduced-motion 状态。

## 最小执行闭环

```text
首页
→ 点击 DO
→ 输入模糊念头
→ 系统理解目标并给出一个最小动作
→ 用户选择：现在开始 / 先放着
→ 执行后回来记录
→ 记录进入时间线
→ 可生成分享页
→ 回到首页
```

建议文案要自然、简短，避免鸡汤和产品腔。不要继续使用“今天，先做一点。”。

可探索的方向：

- “有件事，想现在试试吗？”
- “先把这个念头放下来。”
- “现在只做一小步。”

最终文案需要根据视觉方向统一决定，不要同时堆很多句子。

## 记录功能

记录不应该只从 DO 进入，也可以独立创建。

创建记录：

- 文字
- 图片
- 视频
- 可选关联一个之前的 DO
- 创建记录后，相关 DO 自动进入“已记录”状态
- 不需要单独维护“已完成”状态

时间线：

- 采用纵向时间轨迹
- 按真实发生时间排列
- 一条记录可以只有一句话，也可以包含图片或视频
- 日常、重复、普通、不起眼的事情也值得记录
- 不做社交信息流，不显示点赞、评论、关注等指标

记录的感觉应该像：

> 把生活中真实发生的一页留下来。

## DO 历史

- 首页底部最多展示一条最近 DO。
- 其他 DO 默认折叠。
- 点击后展开历史清单。
- 待定 DO 经过一段时间，例如 24 小时后，自动收进历史清单。
- 用户可以手动划掉或移除 DO。
- 抽签功能是后续可选功能，不属于当前 MVP。

## 分享功能

- 重点不是强迫用户分享，而是先把记录生成得足够好。
- 分享页应该可以直接发到社交账号。
- 风格参考小红书、Instagram 的内容完成度，但不照搬信息流结构。
- 分享内容可以是文字、图片、视频的高质量组合。
- 不要加入点赞数、评论数、关注数等社交压力元素。

## 视觉方向

当前应该从视觉上完全重启，不在旧模板上继续修补。

期望：

- 私人生活杂志 / 现代生活影集
- 精致、克制、暗系
- 有真实摄影感
- 主次分明
- 前景、中景、背景有层次
- 视觉有引导，但不堆组件
- 动效有物理感和连续性
- 页面让人产生记录欲望

明确不要：

- 普通社交 App 首页
- Todo 列表
- Dashboard
- 底部 Tab 导航
- 卡片堆叠
- 随机 Picsum 背景作为最终视觉
- 巨大标题压在背景图上
- 发光圆环
- 玻璃拟态面板堆叠
- 胶囊按钮泛滥
- 伪高级的英文眉标题
- 只是换背景、颜色、圆角，却不改变结构

## 技术边界

- 当前是可丢弃 H5 原型，不是生产架构。
- 手机优先，电脑可用。
- React + Motion 可以使用。
- 状态暂存在内存即可。
- 不加账号、数据库、真实发布系统。
- 当前项目路径：`prototypes/first-loop`。
- 运行命令：`npm run prototype`。

## 下一窗口的正确工作方式

1. 先阅读本文件、`intent.md`、`CONTEXT.md`、`PRD.md`。
2. 明确声明 Design Read 和三个设计参数。
3. 先输出 2-3 个真正不同的视觉构图草案，或先制作视觉板，不要直接改代码。
4. 选定一个方向后，先做首页静态构图。
5. 用户确认画面方向后，再接入 DO 共享元素展开动效。
6. 再接入最小行动、记录、时间线和分享页。
7. 每一个阶段都要实际打开浏览器截图检查。
8. 不允许只修改一两行 CSS 就声称重做。
9. 如果当前结构与方向冲突，直接删除重写，不要在旧模板上打补丁。

## 当前工作失败的原因

- 把氛围描述误解成背景主题。
- 把 DO 做成普通 CTA 按钮。
- 输入框与 DO 没有共享元素关系。
- 反复在旧页面上换颜色、背景和圆角。
- 先堆功能，再勉强套视觉。
- 视觉结构、交互结构和产品隐喻没有统一。
- 多次没有截图验证就声称完成。

## 重启成功标准

用户第一次打开页面时，应该能感受到：

1. 这是一个完整、统一、有摄影感的视觉空间。
2. DO 是这个空间里自然存在的核心入口。
3. 点击 DO 时，它真的像一个物件一样展开，而不是弹出表单。
4. 用户知道如何写下念头、开始行动、回来记录。
5. 时间线和分享记录是自然延伸，而不是额外拼接的功能模块。
6. 页面不会让人联想到普通 Todo、社交 App 或 AI Dashboard。
